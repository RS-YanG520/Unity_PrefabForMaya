# Maya 2018 插件（Unity MayaToUnity）可行性分析

## 1. 背景与目标

目标：写一个 Maya 2018 插件，功能对标 **UnrealToUnity**——把 Maya 里通过实例复制（Duplicate Special / instance）创建的模型实例，导出为 Unity 的 Prefab，并按实例各自的世界变换摆回场景，避免同一网格在 Unity 里被展开成多份重复几何体。

约束：

- Maya **2018**，插件用 **Python 2.7** 编写；
- 目标工程为 Unity **2021.3**（**Built-in 渲染管线**）。

## 2. 结论概览

| 功能 | 可行性 | 说明 |
|---|---|---|
| 手写 Unity 文本资产（.unity/.prefab/.mat/.meta） | ✅ 可行 | UnrealToUnity 已用同样方式验证；Unity 资源就是 YAML 文本 + GUID/fileID 引用 |
| 导出 FBX（含 mesh 几何） | ✅ 可行 | `cmds.FBXExport`，加载 `fbxmaya` 插件即可 |
| 控制 FBX 内 mesh 的 fileID | ✅ 可行 | 用 `.meta` 的 `fileIDToRecycleName` 固定，无需复刻 Unity 名字哈希 |
| 识别 Maya 实例 | ✅ 可行 | 实例共享同一 mesh shape，`listRelatives(shapes=True)` 即可分组，比 Unreal 侧做几何签名更简单 |
| 生成 Prefab | ✅ 可行 | 手写 `.prefab`，引用 FBX 内固定 fileID 的 mesh |
| 材质映射（颜色/贴图/金属度/粗糙度） | 🟡 部分可行 | 主颜色、主贴图、Arnold metalness/roughness 可映射；复杂 shading network 不可行，需烘焙 |
| 贴图导出 | ✅ 可行 | 复制 `file` 节点的源贴图文件 |
| 坐标/单位/轴系转换 | ✅ 可行 | Maya 世界矩阵手工分解为位置 + 四元数 + 缩放 |
| 骨骼/蒙皮/动画 | ❌ 不可行（第一版） | FBX 可带，但 Prefab 侧 SkinnedMeshRenderer 与绑定关系手写复杂度高 |
| 灯光/相机导出 | 🟡 可做但第一版不导出 | 场景只生成基础摄像机 + 平行光 + 网格实例 |

## 3. 关键技术可行性论证

### 3.1 手写 Unity YAML（核心机制）

Unity 的资源文件（`.unity`、`.prefab`、`.mat`、`.meta`）本质是 YAML 文本，资源之间的引用统一靠「GUID + fileID」两要素：

```
{fileID: 4300000, guid: <32位hex>, type: 3}
```

- **GUID**：写在资源的 `.meta` 里，标识一个资源文件；
- **fileID**：标识资源文件内部的对象（GameObject、Transform、Mesh、材质主对象等）。

UnrealToUnity 已经证明：只要这两要素对得上，Unity 完全接受外部手写的文件。因此 Maya 插件可以：

1. 用名字的 MD5 生成确定性 GUID（同一名字永远得到同一 GUID）；
2. fileID 采用与 UnrealToUnity 一致的固定约定（mesh=4300000、材质=2100000、贴图=2800000、Prefab 源=100100000 等）。

**结论：可行。**

### 3.2 控制 FBX 内 mesh 的 fileID

Unity 导入 FBX 时，默认用「对象名哈希」给 FBX 内对象分配 fileID，这个哈希算法不公开、难以复刻。但 UnrealToUnity 找到了正确做法——在 FBX 的 `.meta` 里写 `fileIDToRecycleName` 表：

```yaml
ModelImporter:
  fileIDToRecycleName:
    100000: //RootNode
    400000: //RootNode
    2300000: //RootNode
    3300000: //RootNode
    4300000: <MeshName>
    4300002: <MeshName>
```

Unity 导入时按此表给对应名字的对象分配固定 fileID，于是 `.prefab` / `.unity` 里就能用确定值引用 FBX 内的 mesh。

**关键点**：`4300000` 对应的 key 必须是 FBX 内 mesh 节点的**精确名字**。当前导出使用固定临时名 `__MTU_Mesh__` 写入 `.meta` 的 `fileIDToRecycleName`，已实测可稳定引用。

**结论：可行，但需实测验证 mesh 名匹配。**

### 3.3 识别 Maya 实例

Maya 的 Duplicate Special（instance）会让多个 transform 共享同一个 mesh shape。因此「多个 transform 的 shape 相同」即是一个实例组：

```python
shapes = cmds.listRelatives(transform, shapes=True, noIntermediate=True)
```

按 shape 分组，成员数 ≥ 2 的即为实例组。这是 Maya 相对 Unreal 的天然优势——不需要做几何签名比对，直接靠节点共享关系即可。

**结论：可行，且比 Unreal 侧更简单可靠。**

### 3.4 材质 / 贴图映射

Maya 材质 → Built-in Standard 材质的映射范围：

| Maya | Unity Standard | 可行性 |
|---|---|---|
| `baseColor` / `color` | `_Color` | ✅ |
| 主颜色连接的 `file` 节点 | `_MainTex` | ✅ |
| Arnold `metalness` | `_Metallic` | ✅ |
| Arnold `specularRoughness` | `1 - _Glossiness` | ✅ |
| 程序纹理 / 混合节点 / 颜色校正 | —— | ❌ 需先烘焙 |

默认材质（`lambert1`、`standardSurface1` 等）跳过不导出。

**结论：基础材质可行；复杂 shading network 超出第一版范围。**

### 3.5 坐标 / 单位 / 轴系转换

- Maya：Y-up、右手系、单位 cm；矩阵按行向量 `p' = p * S * R * T`。
- Unity：Y-up、左手系、单位 m。

**已实测通过**（桶实例 / 非实例、非均匀缩放）：

```
位置  : (-x/100, y/100, z/100)     # cm→m；X 取反（视口 X 相反），Z 不取反
旋转  : S·R·S（S=diag(-1,1,1)）→ 四元数 → 共轭
缩放  : 世界矩阵 3x3 的**行**长度（非列；列在「非均匀缩放+旋转」时会算错）
```

**结论：可行，且第一版坐标链路已对齐 Maya 场景。**

## 4. 方案选型

| 方案 | 描述 | 优点 | 缺点 |
|---|---|---|---|
| **A：Maya 直接手写 Unity YAML** ✅ | Maya 侧生成 Unity 文本资产，导出即用 | 一次到位、最像 UnrealToUnity、无需 Unity 侧工具 | 需精确复刻 YAML 格式，对 Unity 版本敏感 |
| B：FBX + Unity 侧 C# 后处理 | Maya 只导 FBX，Unity 里脚本生成 Prefab | 稳健、复用 Unity 官方 API | 两步操作，需维护 Unity 侧代码 |
| C：FBX + 元数据 JSON | Maya 导出 FBX + 实例信息，Unity 读取重建 | 数据与逻辑分离 | 仍需 Unity 侧解析脚本 |

**选择：方案 A**——与 UnrealToUnity 技术路线一致，单侧（Maya）完成全部工作，产物直接是 Unity 项目目录。

## 5. 最终方案设计（已实现）

- **实例处理**：识别共享 shape 的实例组，每组生成一个 Prefab；
- **FBX 导出**：临时复制 → 独立几何 → 世界矩阵归零 → 导出对象空间网格（避免双重变换）；
- **场景层级**：祖先空组写成空 GameObject，mesh 为 PrefabInstance，按本地 TRS 挂到父 Transform；
- **多材质**：同一 mesh 多个 shadingEngine / 按面赋材质 → Prefab 多个 Materials 槽（按最小面号排序）；
- **导出范围**：不选中 → 导出整个场景；选中 → 只导出选中；
- **产物结构**：`Models/*.fbx`、`Prefabs/*.prefab`、`Materials/*.mat`、`Textures/*`、`MayaToUnity.unity`。

## 7. 遗留风险 / 后续项

1. 贴图的 UV 平铺/偏移与颜色校正节点未处理。
2. 复杂材质、骨骼动画不在第一版范围内。
3. 二进制 FBX 无法文本解析 mesh 名时依赖固定导出名 `__MTU_Mesh__`（当前已稳定）。
4. 中间被跳过的非导出节点（如默认相机壳）会把子节点挂到更上层祖先，本地 TRS 已按该 Unity 父重算。
