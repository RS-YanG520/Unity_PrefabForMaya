# Maya 2018 插件（Unity MayaToUnity）可行性分析

## 1. 背景与目标

目标：写一个 Maya 2018 插件，功能对标 **UnrealToUnity**——把 Maya 里通过实例复制（Duplicate Special / instance）创建的模型实例，导出为 Unity 的 Prefab，并按实例各自的世界变换摆回场景，避免同一网格在 Unity 里被展开成多份重复几何体。

约束：

- Maya **2018**，插件用 **Python 2.7** 编写；
- 目标工程为 Unity **2021.3**（**Built-in 渲染管线**）。

参考实现：仓库根目录 `UnrealToUnity/`（已从 `Assets/` 移出，避免 Unity 编译 `.Build.cs` 报 CS0246）。

## 2. 结论概览

| 功能 | 可行性 | 说明 |
|---|---|---|
| 手写 Unity 文本资产（.unity/.prefab/.mat/.meta） | ✅ 可行 | UnrealToUnity 已用同样方式验证；Unity 资源就是 YAML 文本 + GUID/fileID 引用 |
| 导出 FBX（含 mesh 几何） | ✅ 可行 | `cmds.FBXExport` Binary；`.meta` 用 `fileIDToRecycleName` 固定 mesh fileID |
| 识别 Maya 实例 | ✅ 可行 | 共享同一 mesh shape（UUID）分组，比 Unreal 几何签名更简单 |
| 生成 Prefab / 场景层级 | ✅ 可行 | Prefab + 空组 GameObject + PrefabInstance，本地 TRS 挂父 |
| 材质 / 贴图（主色/主贴图/金属度/法线） | 🟡 部分可行 | 基础通道可映射；复杂 shading network 需烘焙 |
| 贴图拖放（AE / 材质球 / 视口） | ✅ 可行 | PySide2 拖放 + MEL AE 按钮；可配置后缀规则 |
| 坐标 / 单位 / 轴系转换 | ✅ 可行 | 位置 X 取反 + cm→m；旋转 S·R·S；缩放取行长度 |
| 内置灯光导出 | ✅ 可行 | directional / spot / point → 场景 Light；ambient → RenderSettings |
| UV 通道查看 / 改名 | ✅ 可行 | 诊断表 UV0/UV1；双击或批量右键 `polyUVSet` 重命名；无 UV1 时可从 UV0 复制 |
| 骨骼 / 蒙皮 / 动画 | ❌ 非第一版 | Prefab 侧 SkinnedMeshRenderer 手写复杂度高 |
| Maya 相机导出 | ⏳ 未做 | 场景仍用模板 Main Camera |

## 3. 关键技术可行性论证

### 3.1 手写 Unity YAML（核心机制）

Unity 的资源文件（`.unity`、`.prefab`、`.mat`、`.meta`）本质是 YAML 文本，资源之间的引用统一靠「GUID + fileID」两要素：

```
{fileID: 4300000, guid: <32位hex>, type: 3}
```

- **GUID**：写在资源的 `.meta` 里，标识一个资源文件；
- **fileID**：标识资源文件内部的对象（GameObject、Transform、Mesh、材质主对象等）。

UnrealToUnity 已经证明：只要这两要素对得上，Unity 完全接受外部手写的文件。因此 Maya 插件可以：

1. 用名字的 MD5 生成确定性 GUID（同一名字永远得到同一 GUID）；
2. fileID 采用与 UnrealToUnity 一致的固定约定（mesh=4300000、材质=2100000、贴图=2800000、Prefab 源=100100000 等）。

**结论：可行。**

### 3.2 控制 FBX 内 mesh 的 fileID

Unity 导入 FBX 时，默认用「对象名哈希」给 FBX 内对象分配 fileID，这个哈希算法不公开、难以复刻。正确做法是在 FBX 的 `.meta` 里写 `fileIDToRecycleName` 表，把 mesh 固定为 `4300000`。

**关键点**：`4300000` 对应的 key 必须是 FBX 内 mesh 节点的**精确名字**。Binary FBX 无法文本解析时，回退为导出前设定的 Maya transform 短名。

**结论：可行，已实测。**

### 3.3 识别 Maya 实例

Maya 的 Duplicate Special（instance）会让多个 transform 共享同一个 mesh shape。按 shape 节点 UUID 分组，成员数 ≥ 2 即为实例组。

**结论：可行，且比 Unreal 侧更简单可靠。**

### 3.4 材质 / 贴图映射

| Maya | Unity Standard | 可行性 |
|---|---|---|
| `baseColor` / `color` | `_Color` | ✅ |
| 主颜色连接的 `file` 节点 | `_MainTex` | ✅ |
| Arnold `metalness` | `_Metallic` | ✅ |
| Arnold `specularRoughness` | `1 - _Glossiness` | ✅ |
| 法线 `file` | `_BumpMap` | ✅ |
| 程序纹理 / 混合 / 颜色校正 | —— | ❌ 需先烘焙 |

默认材质（`lambert1`、`standardSurface1` 等）跳过不导出。工具窗口支持一键转 PBR / 还原。

**结论：基础材质可行；复杂 shading network 超出第一版范围。**

### 3.5 坐标 / 单位 / 轴系转换

- Maya：Y-up、右手系、单位 cm。
- Unity：Y-up、左手系、单位 m。

**已实测通过**（桶实例 / 非实例、非均匀缩放）：

```
位置  : (-x/100, y/100, z/100)     # cm→m；X 取反
旋转  : S·R·S（S=diag(-1,1,1)）→ 四元数 → 共轭
缩放  : 世界矩阵 3x3 的**行**长度（非列）
```

灯光另补本地绕 Y 转 180°：Maya 灯沿局部 −Z，Unity Light 沿局部 +Z。

**结论：可行，mesh / 灯光朝向均已对齐。**

### 3.6 内置灯光 → Unity Light

| Maya | Unity | 说明 |
|---|---|---|
| `directionalLight` | `m_Type: 1` Directional | color / intensity；可挂 `m_Sun` |
| `spotLight` | `m_Type: 0` Spot | + coneAngle → spotAngle；range 默认 10m |
| `pointLight` | `m_Type: 2` Point | range 默认 10m |
| `ambientLight` | 不写 Light GO | `color×intensity` → RenderSettings Flat ambient |

- 有场景灯时关闭模板 Directional Light，避免双太阳。
- 阴影：`useDepthMapShadows` / `useRayTraceShadows` → Soft。
- 本版不含 area / Arnold / IES / cookie；强度不做物理单位换算。

**结论：内置灯光可行；环境光勿轻易改 Ambient Mode，以免天空观感发黑。**

## 4. 方案选型

| 方案 | 描述 | 优点 | 缺点 |
|---|---|---|---|
| **A：Maya 直接手写 Unity YAML** ✅ | Maya 侧生成 Unity 文本资产，导出即用 | 一次到位、最像 UnrealToUnity、无需 Unity 侧工具 | 需精确复刻 YAML 格式，对 Unity 版本敏感 |
| B：FBX + Unity 侧 C# 后处理 | Maya 只导 FBX，Unity 里脚本生成 Prefab | 稳健、复用 Unity 官方 API | 两步操作，需维护 Unity 侧代码 |
| C：FBX + 元数据 JSON | Maya 导出 FBX + 实例信息，Unity 读取重建 | 数据与逻辑分离 | 仍需 Unity 侧解析脚本 |

**选择：方案 A**——与 UnrealToUnity 技术路线一致，单侧（Maya）完成全部工作。

## 5. 最终方案设计（已实现）

- **工具窗口**：可停靠 PySide2 工具条（导出路径 / 诊断 / 材质转 PBR / 贴图拖放 / 中英文）；
- **实例处理**：共享 shape 实例组 → 每组一个 Prefab；独立网格各自一份；
- **FBX 导出**：临时复制 → 独立几何 → 世界矩阵归零 → Binary FBX（对象空间）；
- **场景层级**：空组 → 空 GO；mesh → PrefabInstance；灯光 → Light GO；本地 TRS 挂父；
- **多材质**：按面集排序写入 Prefab `m_Materials`；
- **灯光**：内置灯写入 `.unity`；ambient 写 RenderSettings；
- **诊断**：模型 / 灯光分栏列表、UV0·UV1、实例红绿方块、大纲/视口选中双向同步、UV 双击/批量改名；
- **导出范围**：不选中 → 全场景；选中 → 子树内 mesh + 灯；
- **产物结构**：`Models/*.fbx`、`Prefabs/*.prefab`、`Materials/*.mat`、`Textures/*`、`MayaToUnity.unity`、`export_report.log`。

## 7. 遗留风险 / 后续项

1. 贴图的 UV 平铺/偏移与颜色校正节点未处理。
2. 复杂材质、骨骼动画不在第一版范围内。
3. 二进制 FBX 无法文本解析 mesh 名时回退为 Maya transform 短名（写入 `fileIDToRecycleName`）。
4. 中间被跳过的非导出节点（如默认相机壳）会把子节点挂到更上层祖先，本地 TRS 已按该 Unity 父重算。
5. 灯光强度 / 点光范围仅为近似；area / Arnold / IES / cookie 未支持。
6. 导出 ambient 若强制 Flat 环境光，可能使天空观感偏暗——使用时注意 Ambient Mode。
7. Maya 相机未导出；场景仍带模板 Main Camera。
